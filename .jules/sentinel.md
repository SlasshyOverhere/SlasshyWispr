## 2025-02-18 - XSS Risk with innerHTML Template Literals
**Vulnerability:** XSS vulnerabilities existed in functions updating dynamic UI (e.g., `showOfflineModeDiagnostic`, `confirmDestructiveAction`) because `innerHTML` was assigned strings containing interpolated properties (like error descriptions, steps, and confirmation messages) without proper HTML escaping.
**Learning:** Using template literals to assemble complex DOM structures dynamically requires rigorous escaping of any user-controlled input or state derived from external APIs, as modern browser engines will blindly execute scripts injected within these payloads. Applying `.innerHTML` makes it convenient but inherently risky if `escapeHtml()` is forgotten.
**Prevention:** Always wrap dynamically interpolated values in `.innerHTML` template literals with an `escapeHtml()` function. When refactoring or rendering complex elements, prefer using programmatic DOM creation (e.g., `document.createElement`, `textContent`) combined with `.append()` to avoid injection surfaces entirely. Use `white-space: pre-wrap;` in CSS to securely display strings with intentional line breaks (\n).
