## 2025-02-18 - Replacing `innerHTML` with Programmatic DOM Creation
**Learning:** Using `innerHTML` with template literals for dynamically rendering arrays of components incurs significant HTML parsing overhead (and presents a potential XSS vulnerability if inputs are not stringently escaped, despite our `escapeHtml` usage). For DOM list rendering in hot paths like `conversationLog`, `dictionaryList`, `snippetsList`, and `notesList`, generating elements programmatically with `document.createElement`, `textContent`, and `.append()` reduces re-rendering CPU cycles inside the main thread.
**Action:** When updating or rendering lists on the frontend, always use `document.createElement`, `textContent`, and `DocumentFragment.append()` in lieu of `innerHTML`. Attach event listeners directly to instantiated elements instead of querying for them later via selectors.
